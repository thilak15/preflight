5-Dimension Grilling Scorecard

Problem & User Pain 20/20 (stress-tested)

Eliminates yes-man AI validation and post-hoc-only diagramming by forcing Socratic architecture grilling and real GitHub issue pain-point mining before code is written.

  • Developers jumping straight to code without checking Graveyard Repos
  • Post-hoc tools (GitDiagram/DeepWiki) require an existing repo and cannot validate pre-code ideas
Scope & Non-Goals 20/20 (stress-tested)

Scoped as a native Agent Skill (SKILL.md + deterministic Python scripts for state, GitHub scouting, and HTML blueprint rendering) that hands off into /to-spec, /to-tickets, and /tdd.

  • Avoids duplicating host LLM orchestration inside a separate Gemini CLI loop
State & Persistence (Memory) 20/20 (stress-tested)

Hybrid 3-tier persistence: git-friendly JSON/Markdown for Working State (.preflight/state.json) and Decision Ledger (docs/adr/*.md + .preflight/decisions.json), plus SQLite (.preflight/cache.db) with 7-day TTL for GitHub Repo Cache.

  • Downstream coding agents read docs/adr/ and GLOSSARY.md natively without querying SQLite
Bottlenecks & Failure Modes 20/20 (stress-tested)

Mitigates GitHub API rate limits (60/hr unauthenticated) via gh auth token -> GITHUB_TOKEN -> unauthenticated fallback chain, SQLite TTL caching, and noise/spam repo filtering.

  • Unauthenticated fallback automatically reduces query breadth to prevent HTTP 403 rate-limit crashes
  • Keyword-stuffed spam repos are filtered out via in:name,description scoping
Prior-Art Differentiation 20/20 (stress-tested)

Directly solves top mined open issues in OpenSpec (#1176 built-in HTML artifact viewer, #900 SDD-to-TDD bridge) and GitDiagram (#4 & #112 local CLI/repo execution) while avoiding the rigid monolithic process that caused gsd-build/get-shit-done (64k stars) to be archived.

  • Combines live GitHub Graveyard & Pain-Point Mining with mattpocock/skills handoff

Adversarial Red-Team Critique

Double-LLM Orchestration Trap

CRITICAL

Failure Mode / Attack Vector: Building a standalone gemini-2.5-flash CLI inside an AI coding workspace forces users to manage duplicate API keys, splits conversation history, and blocks native file/subagent tool access.

Architectural Mitigation: ADR-0001: Package PreFlight as a host-orchestrated Agent Skill (SKILL.md) paired with deterministic Python helper scripts.

GitHub Search Rate-Limit & Keyword-Spam Poisoning

HIGH

Failure Mode / Attack Vector: Unauthenticated GitHub Search API allows only 10 req/min (60/hr), and broad README searches return keyword-stuffed political/spam repos that pollute Pain-Point Mining.

Architectural Mitigation: Authenticate via gh auth token -> GITHUB_TOKEN -> unauthenticated fallback, scope queries with in:name,description, filter spam heuristics, and cache in SQLite (.preflight/cache.db) with a 7-day TTL.

Opaque SQLite State Hiding ADRs from Coding Agents

HIGH

Failure Mode / Attack Vector: Storing ADRs and Working State exclusively inside a binary SQLite file prevents downstream skills (/to-spec, /to-tickets, /tdd) and git diffs from inspecting architectural decisions.

Architectural Mitigation: ADR-0002: Hybrid persistence — Markdown ADRs (docs/adr/) + JSON state (.preflight/*.json) for humans/agents, and SQLite strictly for Tier 3 Repo Cache.

Decision Ledger (Locked ADRs & Rejected Paths)

ADR-0001

Host-Orchestrated Agent Skill Over Standalone LLM CLI

docs/adr/0001-host-orchestrated-agent-skill.md

Locked Decision: Package PreFlight as a native Agent Skill (SKILL.md + deterministic Python helper scripts) orchestrated by the host agent.

Rationale: Avoids duplicate API keys and split context while keeping GitHub API caching and HTML rendering deterministic.

Rejected Alternatives: Standalone Python CLI loop calling gemini-2.5-flash directly.

ADR-0002

Hybrid Repo-Native Markdown/JSON State and SQLite Repo Cache

docs/adr/0002-hybrid-repo-native-and-sqlite-state.md

Locked Decision: Store Working State and Decision Ledger as git-diffable JSON/Markdown (.preflight/*.json, docs/adr/*.md) and use SQLite (.preflight/cache.db) strictly for Tier 3 GitHub API caching.

Rationale: Downstream coding agents and humans need direct access to docs/adr/ and GLOSSARY.md in version control.

Rejected Alternatives: Single opaque SQLite database for all three memory tiers.
